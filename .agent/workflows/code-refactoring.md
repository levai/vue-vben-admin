# 代码重构工作流

此工作流指导 Agent 在不改变代码外部行为的前提下，如何优化内部结构。

## 必备条件

- 已通过的现有测试（如果存在）。
- 对相关代码逻辑的完整理解。

## 工作流步骤

1.  **影响分析**: 识别受重构影响的模块和依赖。
2.  **制定方案**: 应用设计模式或重构技巧（如“提取方法”、“移动函数”、“替换算法”）。
3.  **小步快跑**: 每次只进行一处微小且完整的修改。
4.  **同步更新文档**: 修改注释和相关的 Markdown 文档。
5.  **验证**: 运行测试或手动验证，确保外部行为一致且未引入回归。

## 最佳实践

- **应当 (DO)**: 优先重构最具复杂性或最具“坏味道”的代码。
- **应当 (DO)**: 保持代码风格与项目现有规范一致。
- **避免 (DON'T)**: 在重构的同时增加新的功能 feature。
- **避免 (DON'T)**: 在没有验证手段的情况下进行大规模重构。

## 示例

**提示词:**

> 将 `UserLoginHelper` 中长达 200 行的 `process` 方法重构为多个私有方法。

**重构思路:**

- 提取数据验证逻辑。
- 提取权限校验逻辑。
- 提取令牌生成逻辑。
- 保持主入口方法清晰直观。
